# 2026-07-07

## Fix HAMi vGPU restore after DRA path change (containers -> claims)

### Context
HAMi migrated its per-allocation vGPU bind-mount directory from the legacy
device-plugin layout `/usr/local/vgpu/containers/<UUID>_<container_name>` to the
DRA layout `/usr/local/vgpu/claims/<ResourceClaim-UID>` (Project-HAMi/k8s-dra-driver,
`cmd/hami-kubelet-plugin/hami_core.go`). The unit of allocation is now the
Kubernetes ResourceClaim rather than the container, hence the `claims` rename.
The hardcoded `hamiVGPUContainersPrefix` no longer matched the new mounts, so no
CRIU `ext-mount-map` entries were emitted and restore failed with
"No mapping for ... mountpoint".

### Changes (internal/lib/restore.go)
- Replaced the single `hamiVGPUContainersPrefix` constant with a
  `hamiVGPUMountPrefixes` slice holding both the current `claims` prefix and the
  legacy `containers` prefix, so checkpoints taken on one HAMi version can be
  restored on another and future renames only need a new list entry.
- Added `hasHAMiVGPUPrefix` helper and used it in `extractHAMiVGPUSources` and
  `buildHAMiExtMountMapLines` in place of the single-prefix check.
- Updated the `hamiDRALabel` comment to reflect the container-UUID vs
  ResourceClaim-UID directory naming.

### Tests (internal/lib/restore_internal_test.go, new white-box package lib)
- Detection of the DRA `claims` mount.
- Backward-compatible detection of the legacy `containers` mount.
- ext-mount-map remap for the `claims` layout.
- Cross-version remap (legacy `containers` checkpoint restored onto a `claims`
  host) paired positionally.

Verified with `go build`, `go vet`, and `go test -tags test ./internal/lib/`.

## Make HAMi vGPU mount prefixes configurable

### Context
HAMi tends to change its vGPU mount path across versions, so a hardcoded list
becomes outdated. Exposed the prefixes as a CRI-O runtime configuration option
so operators can track future changes without rebuilding, while shipping the
current values as defaults.

### Changes
- pkg/config/config.go: added exported `DefaultHAMiVGPUMountPrefixes`
  (claims + containers), new `RuntimeConfig.HAMiVGPUMountPrefixes` field with
  toml tag `hami_vgpu_mount_prefixes`, and wired the default in `DefaultConfig`.
- pkg/config/template.go: added the template string and registration so the
  option renders in the generated `crio.conf`.
- internal/criocli/criocli.go: added the `--hami-vgpu-mount-prefixes` CLI flag
  (env `CONTAINER_HAMI_VGPU_MOUNT_PREFIXES`) and its read-back into the config.
- docs/crio.conf.5.md and docs/crio.8.md: documented the new option (required
  by the docs-validation CI gate).
- internal/lib/restore.go: removed the hardcoded package-level prefix list;
  `ContainerServer.hamiVGPUMountPrefixes()` returns the configured value and
  falls back to `DefaultHAMiVGPUMountPrefixes` when unset/empty. The prefixes
  are threaded through `readHAMiVGPUSourcesFromImage`,
  `readHAMiVGPUSourcesFromArchive`, `extractHAMiVGPUSources`,
  `writeDeviceRestoreMetadata`, `buildHAMiExtMountMapLines`, and
  `hasHAMiVGPUPrefix`.

Semantics: a configured list replaces the defaults (standard TOML list
behaviour); an empty/unset list falls back to the built-in defaults.

Verified: `go build`, `go vet`, `go test -tags test ./internal/lib/ ./pkg/config/`,
`go run ./test/docs-validation` (passes), config renders in `crio config`, the
flag appears in `crio --help`, and a `crio.conf` TOML round-trip sets the field.
