# 2026-10-23

## gpu-3 was running the old binary after `make install`

`/usr/local/bin/crio` on gpu-3 was built from `3a0c7a840` (installed 15:39 KST),
but the crio process had started at 14:41 KST and kept executing the replaced
binary (`/proc/<pid>/exe -> /usr/local/bin/crio (deleted)`). A restored HAMi
pod there showed the pre-fix behaviour: config.json with only the directory
remapped and exec'ed processes on the new pod's shared-region path.

Ran `systemctl daemon-reload` and `systemctl restart crio` on gpu-3; the running
process now executes `3a0c7a840` (sha256 20f741a4...). Containers restored
before the restart keep their old config.json and need a new restore.

Check after any install: `sudo ls -l /proc/$(pgrep -x crio)/exe` must not end in `(deleted)`.
