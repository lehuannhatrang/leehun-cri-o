# 2026-11-06

Commit 40a6510fb, found while restoring a pipeline-parallel (NCCL send/recv)
FluidCR job (FluidCR examples/statefulset/model-parallel).

## Changes

- `server/checkpoint_utils.go` `processMounts`: `/dev/shm` stays in
  `ignoredMounts`, but a pod-supplied volume there (memory emptyDir) is kept
  (`userMountableIgnoredMounts`). Before, a restored container got the 64 MiB
  sandbox shm while CRIU had recorded the 8 GiB emptyDir; NCCL then failed with
  `failed to extend /dev/shm/nccl-* ... No space left on device` and the worker
  died right after resume.
- `server/checkpoint_utils.go` `updateAnnotations`: copies
  `io.kubernetes.container.restartCount` from the create request. The
  checkpoint's value made kubelet reuse an attempt number after the restored
  container exited, looping on "error reserving ctr name ... name is reserved".
- `internal/lib/restore.go`: the HAMi vGPU remap runs when the pod has the
  `hami.io/dra` label OR the restored spec bind-mounts a directory under
  `hami_vgpu_mount_prefixes` (`specHasHAMiVGPUMount`). Pods that declare their
  ResourceClaim themselves (namespaces the HAMi webhook skips) never got the
  label, and CRIU failed with `mnt: No mapping for <id>:(null) mountpoint`.

## Tests

New unit tests in `server/checkpoint_utils_test.go` and
`internal/lib/restore_internal_test.go` (`go test -tags test`). The server
suite shows 169 passed / 3 failed both before and after the change; the three
"should fail because archive contains ..." ContainerRestore specs fail on the
unmodified tree as well.

## Deployment

Built and installed by the user on gpu-1 and gpu-3 (running binaries contain
the new functions). storage-gpu-0 still runs the old CRI-O 1.34.3.

## Verified

FluidCR 3-stage pipeline job: partial restore on gpu-1 (gen 1 and gen 2), full
checkpoint of all ranks, gpu-1 V100 -> gpu-3 RTX 5090, again on gpu-3, and
gpu-3 -> gpu-1. All ranks resumed in lockstep; restored containers stayed at
restartCount 0 with an 8 GiB /dev/shm.

## Not fixed here

- HAMi-core (libvgpu.so) `cuMemCreate` hook reads an uninitialized device id for
  host-located allocations (NCCL >= 2.24), writes past the shared region and
  segfaults restored workers. Worked around in the pod spec with
  `NCCL_CUMEM_HOST_ENABLE=0`.
- gpu-1 lost `/run/hami` (bind-mounted by HAMi's CDI spec) after a reboot;
  `/etc/tmpfiles.d/hami.conf` now recreates it.
